# 开源整理与发布说明

## 当前文件布局

保留 `Code/`、`Data/`、`Result/` 的大小写和路径，避免破坏配置与脚本中的相对引用。核心实现集中在 `Code/a500/`；`Code/data_pipeline/` 等目录目前主要是协作边界说明，不应理解为已经拆分完成的独立模块。

| 内容 | 处理方式 |
| --- | --- |
| Code/a500、入口脚本、配置、测试 | 进入源码发布目录 |
| docs、scripts、GitHub 模板与 CI | 进入源码发布目录 |
| 数据字典、Wind 导出说明、数据目录 README | 进入源码发布目录 |
| Data 下实际数据及因子缓存 | 保留本地，不进入源码发布目录 |
| Result 下研究输出、models 下训练模型 | 保留本地，不进入源码发布目录 |
| Report 下私人修订稿、Presentation、归档、tmp | 保留本地，不进入源码发布目录 |
| 根目录课程任务说明及生成器 | 保留本地，不进入源码发布目录 |

报告存在多个修订版本，当前未自行指定“最终版”，也没有删除或移动它们。需要展示报告时，建议后续人工选定一个版本，并核实其中数据、署名和图表的公开权限。

## 已发现的发布障碍

当前 Git 索引跟踪了 `Data/factor_store/` 中的实际因子文件，以及 `models/` 中的训练模型，与原 README 的排除声明不一致。`.gitignore` 只能阻止新文件被自动加入，不能移除已经跟踪的文件，更不能清除历史提交。旧 CI 的全量保护目录检查与这些既有已跟踪文件矛盾。本次改为阻止当前变更新增或修改私有数据和本地输出；这并不表示旧文件已获公开授权或历史已清理。

本次整理不修改 Git 索引、不重写历史、不推送。若公开现有 GitHub 仓库，必须先审查当前文件与全部历史中的数据授权、个人信息及凭据。训练模型和聚合结果是否可以公开也不能仅凭文件格式判断。

## 生成独立发布目录

在项目根目录执行，目标必须尚不存在：

```bash
python scripts/export_public.py --output dist/public-source
```

导出只读取 Git 跟踪或未忽略的文件，再按源码白名单筛选；不会复制 `.git`、实际数据、模型、研究报告或回测结果。每次导出附带 SHA-256 文件清单。此过程不等于敏感信息扫描，代码和配置中的文本仍需复核。

在导出目录中安装环境并验证：

```bash
python -m pip install -r Code/requirements-dev.txt
pytest Code/tests -q
python Code/run_pipeline.py demo --config Code/config.json
```

若要避免将旧历史带入公开项目，可以在复核后的发布目录建立新的 Git 仓库，再推送至选定的公开仓库。不要将原目录的 `.git` 复制进去。

## 许可证

当前没有开源许可证，公开可见本身不授予开源许可。发布前由代码权利人确认共同作者及第三方来源，选定 MIT、Apache-2.0 等合适许可证并添加根目录 `LICENSE`。数据授权与代码许可分别处理；不要给 Wind 数据套用代码许可证。

## 最终包合并后的数据边界

最终产品源代码位于 `Code/product/`，其本地行情、因子和预测默认放在 `Data/product/`，该目录除 README 外忽略 Git。`Result/reproduced/` 为本地重算输出。`Result/reference/` 保存最终包的汇总 CSV、报告和参考图，不新增逐股票预测及持仓 parquet。最终报告 PDF 单独保留在 `Report/`。原仓库已经跟踪的历史数据、预测和模型并未因本次整理自动删除，发布历史审查仍适用。

源码导出工具采用保守白名单，不携带模型、数据、产品冻结报告或原 Git 历史；它与保留研究成果的当前仓库用途不同。
